# 本地代理重加密服务 (Python)

一套可在本地完整运行的**单向、单跳代理重加密 (Proxy Re-Encryption, PRE)**
服务。数据属主可以把“面向自己的密文”的解密能力委托给其他用户；半可信的
代理服务器只负责密文转换，**全程接触不到明文，也接触不到任何一方的私钥**。

服务通过 HTTP 暴露，密钥生成、加解密、重加密密钥生成都在客户端本地完成，
仅依赖 SQLite 持久化，无需任何外部服务。

## 快速开始

```bash
uv sync
uv run uvicorn main:app --port 8000   # 启动服务
uv run pytest                          # 运行自动化测试
```

健康检查：`GET /health`。

## 密码学构造

### 曲线与配对

* 自包含的纯 Python **BLS12-381** 实现（`pre/bls12_381.py`）：Fp/Fp2/Fp12
  塔式扩域、G1/G2 点运算、最优 ate Miller loop、Frobenius 快速最终指数化。
* `e: G2 x G1 -> GT` 满足双线性 `e(aQ, P) = e(Q, aP) = e(Q,P)^a` 且非退化。
  实现与审计过的 py_ecc 参考实现（开发期对照，运行期零依赖）结果逐字节一致。

### 单向重加密方案（Type-3 AFGH）

用户私钥为标量 `a`，公钥包含 `pk1 = a*g1`、`pk2 = a*g2`，
`Z = e(g1, g2)`。

| 算法 | 内容 |
| --- | --- |
| 重加密密钥 A→B | `rk = g2^(b/a)`，**只能由属主 A** 用 `a` 生成 |
| 二级密文（可转换） | `U = g1^(a·r)` + 用 `K=KDF(Z^r)` 加密的 DEM 密文 |
| 代理转换（一次配对） | `V = e(U, rk) = Z^(b·r)`，输出一级密文 |
| 属主 A 解密二级密文 | `K = KDF(e(U, g2)^(1/a))` |
| 被委托人 B 解密一级密文 | `K = KDF(V^(1/b))` |

DEM 采用基于 HMAC-SHA256 的**先加密后认证 (encrypt-then-MAC)** 流密码，
任何对密文体或头部的篡改都会在 MAC 校验阶段被明确拒绝（`TamperError`）。

### 安全模型与“不可转移/合谋安全”的准确边界

* **代理不触明文/私钥**：转换只做一次配对，输入是 `U` 与 `rk`，输出是
  GT 中的 `V`；服务器从不保存任何私钥。
* **抗合谋 (Master Secret Security)**：即使被委托人 B 与代理合谋，在
  DL/co-CDH 假设下也无法恢复属主私钥标量 `a`，无法冒充属主对新数据签名，
  也无法反向推导 B→A 的重加密密钥（单向）。
* **单跳、不可继续转换**：一级密文结构上无法再次重加密（接口返回
  `FormatError`），转换链不可传递。
* **关于“面向第三方的再委托”**：这是 PRE 理论中的“不可转移性”。纯
  PKE 型 AFGH 是“主秘密安全”的经典实现，但被委托人与代理合谋可得到弱秘密
  `g2^(1/a)`，理论上能据此拼出 A→C 的转换材料。学界已证明：在没有额外
  假设（如令牌隔离、条件/基于身份、多服务器门限）时，**密码学层面的绝对
  不可转移性是开放难题**。本服务通过两层措施落实需求：
  1. **服务端授权强约束**：重加密密钥只能由属主本人签名注册，代理只接受
     已登记的 `(属主, 被委托人, 版本)` 三元组；任何非属主发起的委托创建/
     撤销都被拒绝并写入审计（`tests/test_service_api.py` 覆盖越权场景）。
  2. 弱秘密 `g2^(1/a)` 无法恢复标量 `a`，因此属主身份（签名权、对未来密钥
     的控制权）不会被接管。

## 密钥管理约定

* 私钥 `SecretKey` 是 32 字节标量，**只存在于客户端本地**，永不上线。
* 公钥 `PublicKey = G1(97B) || G2(193B)`，注册后服务端会做曲线/子群校验。
* 重加密密钥 `ReEncryptionKey` 是一个 G2 点（193B），可公开给代理。
* 二进制材料在 HTTP JSON 中使用 URL-safe base64 传输。
* 变更类请求使用 **Schnorr 签名**（G1）对
  `方法 + 路径 + 时间戳 + nonce + 原始请求体` 签名，时间戳允许 ±300s 偏差，
  防止重放与伪造。

## 委托撤销（两种粒度）

* **按单条密文**：`POST /ciphertexts/revoke`。撤销后该 `ciphertext_id`
  不得再被转换；**已经完成的转换结果不受影响**。
* **按时间窗口**：`POST /delegations/revoke` 携带 `not_before`（epoch 秒）。
  到达该时刻后该版本委托失效；未到时间前仍可正常使用。

撤销状态写入 SQLite，进程重启后保持。

## 重加密密钥轮换与并发

* 每次轮换写入一个**单调递增的新版本**（`version`），旧版本保留用于审计，
  新版本对新转换生效。
* 转换请求可显式 `pin_version`；未指定时锁定当前活动版本。
* 版本选择、撤销判断、密码学转换与结果落库在**同一个序列化事务**中完成
  （`BEGIN IMMEDIATE`），因此轮换与转换并发时，每个请求都基于某个**确定版本**
  完成，不会出现“用旧密钥转换新密文”或“部分应用新密钥”的中间状态。

## 持久化与崩溃恢复

* SQLite 运行在 `WAL` + `synchronous=FULL`，每个逻辑变更都是原子事务，
  崩溃不会产生部分写入。
* 转换接口以客户端提供的 `request_id` 做**幂等**：首个结果落库后，重试同一
  请求返回已存结果并在审计中标记为 `replay`，保证“最多应用一次”，在途请求
  崩溃后可安全重试。

## HTTP 接口

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/health` | 无 | 健康检查 |
| POST | `/users/register` | 无（自证公钥） | 注册用户 |
| POST | `/delegations` | 属主签名 | 创建委托（返回版本号） |
| POST | `/delegations/rotate` | 属主签名 | 轮换重加密密钥 |
| POST | `/delegations/revoke` | 属主签名 | 全量撤销 / 时间窗撤销 |
| POST | `/ciphertexts/revoke` | 属主签名 | 按密文撤销 |
| POST | `/transform` | 无（代理执行） | 幂等重加密转换 |
| GET | `/audit` | 无（本地服务） | 查询审计记录 |

变更请求需要请求头：`X-User`、`X-Timestamp`、`X-Nonce`、`X-Signature`。

错误以可区分的 JSON 返回：

| code | HTTP | 含义 |
| --- | --- | --- |
| `FormatError` | 422 | 格式非法 / 参数不匹配 / 二级密文重复转换 |
| `TamperError` | 422 | 密文被篡改、MAC 校验失败 |
| `AuthError` | 401 | 签名失败或越权操作 |
| `RevokedError` | 409 | 委托或密文已撤销 / 时间窗已生效 |
| `NotFoundError` | 404 | 用户或委托版本不存在 |
| `ConflictError` | 409 | 重复注册 / 重复撤销等状态冲突 |

## 审计

代理执行的**每次转换**（成功、被拒、重放）以及注册、委托创建、轮换、撤销、
越权尝试都会写入只增的 `audit_log`，可通过 `GET /audit` 按时间倒序查询，
越权操作可追溯。

## 代码结构

```
pre/
  bls12_381.py   # BLS12-381 曲线与最优 ate 配对
  crypto.py      # AFGH 单向重加密 + AEAD DEM
  auth.py        # Schnorr 请求签名/验签
  storage.py     # SQLite 持久化、版本、撤销、幂等、审计
  service.py     # 业务逻辑与授权
  schemas.py     # HTTP 模型 / base64
  api.py         # FastAPI 路由
  client.py      # 本地客户端 SDK（私钥不出本机）
tests/           # 密码学、服务、撤销、并发、崩溃恢复测试
```
